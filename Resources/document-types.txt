# Owlink's text file types: one CFBundleDocumentTypes entry each, with its own
# document icon (Resources/DocIcons/<icon>.icns, made by tools/icon/doc_icons.py).
#
# Ranks (the last column, the entry's LSHandlerRank: "None" or "Alternate"):
# which app opens what without a choice must stay what 0.2.x set up. 0.2.x
# had one Text entry at Alternate claiming exactly public.text,
# public.plain-text, public.source-code, public.script, public.json,
# public.yaml, public.html, public.xml, public.css,
# net.daringfireball.markdown, public.log and public.data; every other claim
# here is None. Launch Services binds a type to the app with the most
# specific claim before it looks at rank, so an exact claim even at
# Alternate wins: "public.css" at Alternate beat Safari's and VS Code's on a
# test Mac, and on a clean macOS 26 an exact Alternate claim took md, json
# and yaml from TextEdit. Finder then draws the icon of the entry whose
# claim won, so each of those exact Alternate claims sits in its labelled
# row (TXT, MD, JSON, YAML, XML, HTML, CSS at Alternate), not in the "*"
# row, or Finder shows the unlabelled icon for a file Owlink opens by
# itself. Every content type keeps 0.2.x's rank and is claimed by one row
# only (DocumentTypesTests checks both).
# LOG stays None: its row also claims com.apple.log, and Alternate there
# would be a new claim that could take .log files from Console. So
# public.log stays in "*", and a .log file Owlink opens without a choice
# shows the unlabelled icon until the user picks Owlink for Log File
# (Settings sets com.apple.log). The other labelled rows are None and never
# make Owlink the default on their own; once the user picks Owlink for one
# (Settings or Get Info › Change All), Finder takes the icon from its row.
# Scripts/bundle-app.sh builds Info.plist from this file; DocumentTypes.swift
# (Settings › Default editor for…) has the same list, and a unit test keeps
# the two in step. Scripts/doctypes-check.sh checks a built app against it.
#
# label | icon | name | content types (first = the one Settings sets) | imported declaration | rank
# The fifth column is "-" for a type the system declares, else
# "<conforms to, comma-separated>;<extensions, comma-separated>": declared
# only for types macOS's CoreTypes lacks, with the identifiers Apple's Xcode
# already uses for them, so the declarations agree. Markdown is in CoreTypes
# from macOS 26 but not in 15 (a .md file there is a dyn.… type nothing
# opens); where the system declares it, Owlink's import is inactive.
# The "*" row is the catch-all for any other text, with the unlabelled icon.
