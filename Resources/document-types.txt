# Owlink's text file types: one CFBundleDocumentTypes entry each, with its own
# document icon (Resources/DocIcons/<icon>.icns, made by tools/icon/doc_icons.py).
#
# Ranks (the last column, the entry's LSHandlerRank: "None" or "Alternate"):
# which app opens what without a choice must stay what 0.2.x set up. 0.2.x
# had one Text entry at Alternate claiming exactly public.text,
# public.plain-text, public.source-code, public.script, public.json,
# public.yaml, public.html, public.xml, public.css,
# net.daringfireball.markdown, public.log and public.data; 0.5.3 kept that
# entry as the "*" row and added the labelled rows, all at None.
# Launch Services binds a type to the app with the most specific claim
# before it looks at rank, so an exact claim even at Alternate can win: an
# exact "public.css" claim at Alternate beat Safari's and VS Code's on a
# test Mac, and on a clean macOS 26 VM 0.5.3's "*" row took md, json and
# yaml from TextEdit. Finder then drew the "*" row's unlabelled icon for
# them, and still did after Owlink was set for them by hand (the binding
# was already Owlink's, via "*"), while every type that a hand-set moved
# from another app to Owlink (txt, xml, html, css, log and the rest) showed
# its labelled icon.
# So MD, JSON and YAML (only those) are Alternate and their types are not
# in "*": the same three types stay Owlink's by default, now with their
# own icons. TXT, XML, HTML and CSS stay None with their types in "*", as
# in 0.5.3. Moving those four too was tried: on a clean macOS 26 VM their
# labelled single-type rows at Alternate took public.xml and public.css
# from Safari right after install, where "*" (the same exact claims among
# twelve) had not; html and txt stayed Safari's and TextEdit's. LOG stays
# None too (Alternate there would also claim com.apple.log). The Alternate
# claims together are exactly 0.2.x's twelve, each once, and every other
# claim is what 0.5.3 had (DocumentTypesTests and doctypes-check.sh check
# both). A labelled None row never makes Owlink the default on its own;
# when the user picks Owlink for its type (Settings or Get Info › Change
# All) and that moves the type from another app, Finder takes the icon
# from that row. A txt, xml, html, css or log file that Owlink opens
# through "*" without a choice (a Mac where TextEdit, Safari or Console
# doesn't claim it) shows the unlabelled icon.
# Scripts/bundle-app.sh builds Info.plist from this file; DocumentTypes.swift
# (Settings › Default editor for…) has the same list, and a unit test keeps
# the two in step. Scripts/doctypes-check.sh checks a built app against it.
#
# label | icon | name | content types (first = the one Settings sets) | imported declaration | rank
# The fifth column is "-" for a type the system declares, else
# "<conforms to, comma-separated>;<extensions, comma-separated>": declared
# only for types macOS's CoreTypes lacks, with the identifiers Apple's Xcode
# already uses for them, so the declarations agree. Markdown is in CoreTypes
# from macOS 26 but not in 15 (a .md file there is a dyn.… type nothing
# opens); where the system declares it, Owlink's import is inactive.
# The "*" row is the catch-all for any other text, with the unlabelled icon.
